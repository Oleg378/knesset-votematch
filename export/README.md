# export/ — the data contract for the web

Generated by `make data` (`pipeline/positions.py`, then `pipeline/export.py`); never edited by hand — except `quiz_texts.json`, every text the user reads on the site, which is edited by hand and checked by `make check` and the web tests. The web reads these files and nothing else.

| File | Read it when |
|---|---|
| `WEB_CONTRACT.md` | **first** — files, loading, the order of questions, list details, golden cases, composition, the positions page, the texts of the site |
| `quiz_core.json`, `quiz_data.json`, `quiz_bills.json` | the data, fetched by the web in this order |
| `quiz_texts.json` | every text of the site (contract §7): app name, answers, notes, explanation lines, screen labels, the methodology page; bundled into the web's JS and read by the Python reference (`pipeline/texts.py`); numbers are `{placeholders}`, never typed |
| `quiz_data.schema.json`, `quiz_texts.schema.json`, `golden.json` | tests: schema of the merged data; schema of the texts (generated from `web/src/texts.ts`); Python results the TypeScript port must reproduce |
| `stats.json` | the current numbers of the export (statements, lists, bills, MKs, directions, file sizes); `make check` compares the numbers typed in the documents with it |

Reference implementation: `pipeline/quiz_match.py` (closeness, trade-offs), `pipeline/quiz_flow.py` (order of questions), `pipeline/quiz_report.py` (explanations); the whole flow in the terminal — `python3 pipeline/quiz_cli.py --no-save`. How it all works — `docs/TECHNICAL.md`.
