# export/ — the data contract for the web

Generated by `make data` (`pipeline/positions.py`, then `pipeline/export.py`); never edited by hand — except `quiz_methodology.json`, the texts of the methodology page, which is edited by hand and checked by `make check` and the web tests. The web reads these files and nothing else.

| File | Read it when |
|---|---|
| `WEB_CONTRACT.md` | **first** — files, loading, the order of questions, list details, golden cases, composition, the positions page, the methodology page |
| `quiz_core.json`, `quiz_data.json`, `quiz_methodology.json`, `quiz_bills.json` | the data: the core is bundled with the app, the other three are fetched in this order |
| `quiz_methodology.json` | every text of the Methodology page (contract §7): edit it, and the page changes; numbers come from `quiz_data.json` through `{placeholders}` |
| `quiz_data.schema.json`, `quiz_methodology.schema.json`, `golden.json` | tests: schema of the merged data; schema of the methodology texts (generated from `web/src/methodology.ts`); Python results the TypeScript port must reproduce |

Reference implementation: `pipeline/quiz_match.py` (closeness, trade-offs), `pipeline/quiz_flow.py` (order of questions), `pipeline/quiz_report.py` (explanations); the whole flow in the terminal — `python3 pipeline/quiz_cli.py --no-save`. How it all works — `docs/TECHNICAL.md`.
