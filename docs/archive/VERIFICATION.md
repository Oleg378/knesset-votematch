## Уровни проверки

| Уровень | Что это | Кто |
| --- | --- | --- |
| **L0. Инварианты** | Автоматические проверки при каждой сборке: число строк, дубли, пустые ключи, совпадение с подсчётом на сервере | скрипты |
| **L1. Эталон** | Сравнение ответа модели с размеченными вручную данными | скрипт, эталон размечает Claude |
| **L2. Независимый сигнал** | Сверка с данными, которые модель не видела: голосования блоков, статус законопроекта | скрипт |
| **L3. Выборочный разбор** | Чтение конкретных примеров (название, записка, голоса) и вердикт «кто прав» | Claude |
| **L4. Ценностное решение** | Вопросы, где правильный ответ зависит от взглядов или целей проекта, а не от данных | вы |

**Главное ограничение.** Весь эталон (L1) размечен одним человеком — мной, Claude. Это не экспертная разметка. Как минимум в 4 случаях я ошибся сам, и их исправили только записки (см. «Тексты законопроектов» в jef-task.md).

## Правила использования ответов модели

Пороги действуют, пока не пересмотрены. Обоснования — в SHARED_UNDERSTANDING.md (обоснования по ID — в архиве реестра).

**Тема законопроекта:**

| Уверенность | Что делаем |
| --- | --- |
| ≥ 0,8 | принимаем (точность 92 % на эталоне) |
| 0,5–0,8 | принимаем для статистики по партиям; в квиз только после L3 |
| < 0,5 | направление не считаем; законопроект не идёт ни в статистику, ни в квиз без L3 |

**Направление: правило двух сигналов (Q17), одинаковое для всех тем.**

| Название | Название и записка | Итог |
| --- | --- | --- |
| сторона A | сторона A | A, надёжность высокая |
| сторона A | неясно или записки нет | A, надёжность средняя |
| неясно | сторона A | A, надёжность средняя |
| сторона A | сторона B | **спорно** → L3, автоматически не используется |
| неясно | неясно | неясно |

Перед правилом двух сигналов работают два фильтра, одинаковые для всех тем: **применимость** (Q21: законопроект касается спора шкалы, ответ ≥ 0,5, иначе `not_applicable`) и **наличие содержания** (Q22: формальное название без записки → `no_content`).

«Неясно» — балл в пределах 0,5 от середины шкалы (1,5–2,5). Исключений по темам нет (P0).

**Нестабильность.** Повторный запрос с тем же входом меняет сторону у 1–2 законопроектов из 61 (пограничные баллы около 2,5). Поэтому разница меньше 3 % между двумя прогонами — это не улучшение и не ухудшение, а шум.

## Когда нужен разбор с участием Claude (L3)

Обязательно:

0. **Каждый законопроект со статусом «спорно»** (Q17).
1. **После изменения каталога тем или шкалы:** 6–10 уверенных ответов по каждой изменённой оси.
2. **Если доля «нейтрально» по шкале выше 50 %:** 10 примеров, чтобы понять, не о другом ли споре шкала.
3. **Если согласованность с блоками по оси ниже 70 % при n ≥ 10:** разобрать все расхождения. Причиной может быть сама проверка, как с ястребиными законопроектами правой оппозиции.
4. **Перед тем как законопроект станет вопросом квиза:** название, записка, тема, направление и голоса — вручную, без исключений.
5. **При любом новом подходе** (новый тип вопроса к модели, новые входные данные): пилот на эталоне до полного прогона.

## Когда нужно ваше решение (L4)

- Ценностная граница оси, где стороны спорят о самом смысле механизма. Пример — судебная тема: разделение должности юрсоветника одни считают ослаблением неизбранного чиновника, другие — усилением правительства. Такие законопроекты сами попадают в «спорно» по правилу Q17.
- Справочник «фракция → партия 2026» и состав блоков.
- Финальный набор вопросов квиза и их формулировки.
- По желанию: выборочная проверка эталона (20–30 строк). Это единственный способ проверить меня самого.

## Уроки: что было пропущено и почему

**Проверка применимости шкалы (Q21) появилась поздно, хотя была в исходном замысле.** Она была в запросе для песочницы (`touches_haredi_draft` + направление «только если касается»), в первом предложении по осям и в рекомендациях TypeSafe («отдельный вопрос о наличии»). При переходе к каталогу тем снизу вверх тема законопроекта молча стала заменой применимости. Это допущение («тема X → законопроект касается спора X») не было записано и не проверялось. Пропуск не поймали, потому что эталоны направления были подобраны вручную из заведомо подходящих законопроектов, сверка с голосами покрывает только спорные голосования, а высокая доля «нейтрально» была прочитана как проблема формулировки шкалы, а не как неприменимость. Обнаружил пропуск только независимый замер.

**Правила, чтобы не повторить:**

1. **Любой вопрос с допущением** («допустим, законопроект касается X») задаётся вместе с явной проверкой этого допущения. Само допущение записывается в SHARED_UNDERSTANDING.md (обоснования по ID — в архиве реестра).
2. **Выборки для оценки строятся по ответам модели** (случайно или стратифицированно), а не только из подобранных вручную очевидных примеров.
3. **У разметчика и у шкалы различаются «нейтрально» и «неприменимо».** Высокая доля «нейтрально» сначала проверяется как возможная неприменимость.
