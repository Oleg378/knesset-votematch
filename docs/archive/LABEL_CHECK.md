# Систематическая проверка разметки по вопросам квиза

_Порядок, по которому 2026-10-19 проверена тема «Imports and competition» (q42) и по которому проверяются остальные вопросы — по одному за раз. Прогресс — [LABEL_CHECK_PROGRESS.md](LABEL_CHECK_PROGRESS.md). Метки: [У] — утверждено заказчиком, [А] — предложение исполнителя._

## Что проверяем

Все законопроекты, которые разметка относит к теме вопроса (`export/quiz_bills.v2.json` → `by_direction[d]`), — не выборку. Вопрос: соответствует ли законопроект **вопросу** (тексту утверждения) по существу, а не только широкой теме, и в какую сторону.

## Шаги

1. **Материал** (`local/research/scripts/core_full_input.py`, `QS=<q> TAG=<имя> PARTS=<n>`): законопроекты темы, сгруппированные по названию без года (повторное внесение — один пункт); у каждого — текст утверждения, тема с «+» и «−», название, начало пояснительной записки. Нашей метки и знака проверяющий не видит. Части по ~80 пунктов.
2. **Первая проверка вслепую** (агент Opus на часть): `about` / `not_about` / `borderline` и знак.
3. **Вторая проверка вслепую** предложенных снятий (пункты `not_about`) вперемешку с контрольными (`about`) — не меньше трети от числа кандидатов.
   **Смена знака — на полном тексте** [У, 2026-10-19]: если первая проверка предлагает другой знак, вторая проверка этого пункта получает не 260 символов пояснительной записки, а записку целиком до 3 000 символов — столько же, сколько видел Jev при исходной разметке (`local/research/scripts/flip_check.py`). Причина: метка поставлена по полному тексту, и переворачивать её по одному-двум предложениям нельзя. Знак меняется, только если проверка на полном тексте согласна с первой. Если кандидат на снятие проверяется вместе со сменой знака на полном тексте и вторая проверка говорит «спорно», третья проверка видит тот же полный текст (иначе решение принималось бы по меньшему тексту, чем у второй).
4. **Решение** [У]: метка снимается, если две проверки сказали «не про вопрос»; если вторая сказала «спорно» — третья проверка, решение большинством из трёх (`overrides.json` «remove», `borderline_resolved.csv`). Расхождение знака — двумя проверками, вторая на полном тексте записки («flip»).
5. **Стандартный аудит текста — для каждой темы, без порогов** [У, алгоритм заказчика], на уже очищенной разметке (`statement_audit.py`, `QS=<q>`, тот же промпт): оставить / переписать шире / разделить (если текст получается расплывчатым); при разделении — Jev выбирает часть для каждого законопроекта (`plan4.json`, `jev_split.py --stage4`), части проходят обычный отбор, не прошедшие снимаются, вопрос переходит на подходящую часть, новые тексты — заказчику. Доля «про вопрос» из шага 2 — только наблюдение, решение принимает аудит.
6. **Пересчёт:** коммит входных данных → `make data` → отбор (все вопросы проходят?) → ядро → тесты → коммит экспорта. Запись в прогресс.

## Дополнения, принятые по ходу проверки (2026-10-19 — 2026-10-20) [У]

- **Инструменты.** `local/research/scripts/label_check_step.py <q> merge1|merge2|apply` — сводит результаты проверок, готовит вторую/третью проверку и `flip_in.csv`, применяет снятия и смены знака (`overrides.json`, `borderline_resolved.csv`). Проверку знака на полном тексте готовит `flip_check.py`. Промпты агентов — те же, что в шагах 2–5 (копии — в истории сессии и в `local/research/label_check_q*/`).
- **Пачки.** Темы можно проверять по 4–5 параллельно; несколько входных файлов можно давать одному агенту, если каждый файл судится независимо.
- **Вопрос не проходит отбор после чистки меток** → снимается (решение заказчика, так сняты q23, q39, q94; q41 — ни одна часть после разделения не прошла).
- **Часть после разделения дублирует существующий вопрос** (большинство её законопроектов уже в теме другого вопроса или смысл почти тот же) → без своего вопроса: 165b (q10), 77b (q45), 277g2 (q9/q15), 69a (q63), 80b (q47/q80). Если часть проходит отбор и не дублирует → новый вопрос, текст заказчику (q108 из 117a).
- **Если разделение «убьёт» важный вопрос** (часть с его текстом не проходит отбор) — не делить механически, а спросить заказчика; для q64 выбрана одна общая формулировка на обе части.
- **Законопроект может относиться к нескольким вопросам** — это общее правило; снимать метки только ради отсутствия двойного учёта нельзя (откат q3/q83).
