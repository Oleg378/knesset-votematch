# Технический справочник

_Как устроена обработка данных, формулы вычисляемых признаков и ограничения данных. Решения и их статусы — в [SHARED_UNDERSTANDING.md](SHARED_UNDERSTANDING.md). Обоснования и история решений по ID — в [архиве реестра](archive/decision_registry_2026-10-12.md)._

## Конвейер данных

```
OData v4 (Кнессет)  ──pipeline/──▶  data/            сырые выгрузки JSON, не редактируются, не в git
                                   manual/          ручные таблицы CSV (в git)
                                        │
                     pipeline/build/build.py ────┤ 10_staging.sql     нормализованные таблицы
                                        │ 30_vote_attrs.sql  признаки голосований
                                        ▼
                                   knesset.duckdb   пересобирается целиком за 2–3 секунды
```

Единица хранения — **голос депутата** (`vote_results`). Позиции фракций, блоков и партий из него только вычисляются и нигде не хранятся как исходные данные.

**Скрипты:**

- `pipeline/export_votes.py`, `pipeline/fetch_bills.py` — выгрузка из OData; работают только с израильского IP.
- `pipeline/bill_texts.py` — тексты законопроектов (DOCX) и пояснительные записки.
- `local/research/scripts/jev_issues.py`, `local/research/scripts/jev_direction_all.py` — разметка через Jev; ключ API в `.env`.
- `local/research/scripts/independent_eval.py` — независимый замер.
- `pipeline/cec_parse.py`, `pipeline/cec_match.py` — списки 2026 и сопоставление кандидатов с депутатами.

## Агенты выявления направлений

Слепые агенты (`claude -p`) видят только свой входной файл и пишут только свой выходной; Bash и веб им запрещены. Стоимость по API — поле `total_cost_usd` в логе.

| Что | Задание (промпт) | Запуск | Вход → выход |
| --- | --- | --- | --- |
| Выборка и входы | — | `local/research/scripts/directions_sample.py ids K` / `build K` | `local/jef/directions/order.csv` → `blind/batch_K.jsonl` (название, `text_source`, записка до 2 000 символов) |
| Выявление, пачка из 50 | `local/jef/directions/blind/DISCOVER.md` | `local/jef/directions/run.sh K [model]` (без модели — по умолчанию, Opus) | `blind/batch_K.jsonl` → `blind/batch_K.out.json`, лог `batch_K.log` |
| Пробное сведение синонимов | `local/jef/directions/merge/MERGE.md` | `local/jef/directions/merge/run.sh` (Sonnet) | `merge/build.py` → `merge/input.tsv` → `merge/out.json` |

Пачки 0–1 — файлы `.v1.out.json`; их правительственные законопроекты перезапущены в `batch_g01`, `batch_g01b`.

## Определения вычисляемых признаков

| Признак | Уровень | Определение |
| --- | --- | --- |
| `vote_roster` | депутат × голосование | Все депутаты на дату голосования; интервалы полуоткрытые `[начало, конец)`. Отсутствующие: `result IS NULL` |
| `n_for`, `n_against`, `n_abstain` | голосование | Число голосов «за», «против», «воздержался» |
| `n_present` | голосование | Все строки результата, включая «присутствовал, не голосовал» |
| `p_for` | фракция | `за / (за + против)`. Воздержавшиеся и неголосовавшие в знаменатель не входят |
| `participation` | фракция, блок | `присутствовали / состав на дату` |
| `cohesion` | блок | `max(за, против) / (за + против)` |
| `direction` | блок | «за», если `за > против`; «против», если меньше; при равенстве NULL |
| `accepted` | голосование | `n_for > n_against` |
| `participation_pattern` | голосование | `one_bloc_absent`: участие одного блока < 0,1, другого ≥ 0,4. `low_turnout`: присутствуют < 25. Иначе `normal` |
| `split_pattern` | голосование | См. таблицу ниже |
| `dissenting_factions` | голосование | Фракции коалиции или оппозиции с ≥ 2 голосами «за» или «против», большинство которых пошло против своего блока |
| `pivotal_factions` | голосование | Фракции, которые одни, проголосовав иначе, изменили бы исход |

Значения `split_pattern` проверяются по порядку:

| Значение | Условие |
| --- | --- |
| `no_blocs` | ни у коалиции, ни у оппозиции нет голосующих |
| `one_bloc_only` | у одного из блоков меньше 3 голосующих |
| `consensus` | направления блоков совпадают, оба со сплочённостью ≥ 0,9 |
| `cross_bloc_majority` | направления блоков совпадают, хотя бы один блок расколот |
| `bloc_line` | направления разные, оба блока со сплочённостью ≥ 0,9 |
| `bloc_line_with_dissent` | направления разные, хотя бы один блок расколот |

## Ограничения данных

| # | Ограничение | Последствие |
| --- | --- | --- |
| L1 | Даты внесения частных законопроектов нет: `PublicationDate` пуста у 98 % | Фракцию инициатора на момент внесения точно не определить |
| L2 | В `KNS_Bill` только текущий статус, истории нет | Этап, на котором законопроект застрял, восстанавливается по датам голосований и заседаний комиссий |
| L3 | Решений Министерского комитета по законодательству в OData нет | Основная блокировка частных законопроектов видна только по следствию: коалиция голосует «против» на предварительном чтении |
| L4 | Поимённых голосований в комиссиях нет | Блокировка в комиссии видна только косвенно, по заморозке законопроекта |
| L5 | `IsContinuationBill` пуст | Законопроекты, перенесённые из прошлых созывов, приходится определять по этапу 9 и по старому Id |
| L6 | В дни ротаций в составе 121 депутат (9 голосований), у 4 строк не определён блок | Пренебрежимо мало |
| L7 | Особое большинство для основных законов (61) не проверяется | Исход отдельных статей основных законов может быть неточным |
| L8 | Голосования поднятием рук и тайные не поимённые | Не используются |
| L9 | Сервис OData доступен только из Израиля, страницы комиссии закрыты Cloudflare | Выгрузка — только с израильского IP; страницы комиссии — через браузер заказчика |

## Ловушки при выгрузке

- Сервер отдаёт часть строк дублями (10 439 строк на 10 418 голосований) — в сборке удаляются дубли.
- DuckDB при автоопределении переводит `+03:00` в UTC, поэтому даты читаются как строки.
- `$skip` деградирует к 40-й странице, поэтому большие таблицы листаются по ключу (`Id gt last`). Без `$orderby` страницы пересекаются.
- При числе потоков больше 2 сервер начинает отвечать HTTP 481. Выгрузка идёт в 2 потока, с повторами и кешем по месяцам.
