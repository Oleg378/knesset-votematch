# Как ответы пользователя превращаются в близость к спискам

_2026-10-17. Принято заказчиком [У]: косинусная близость; «не знаю» пропускается; у пар «а/б» вес ½; сжатие подбирается на синтетических пользователях; результат — топ-3 списка с числом бывших депутатов и пометками. Скрипт — `pipeline/quiz_match.py`. Аудит всей цепочки — `METHOD_AUDIT.md`._

## 1. Ответ → число

| Ответ | Значение |
|---|---|
| Полностью согласен | +1 |
| Скорее согласен | +0,5 |
| Нейтрально | 0 |
| Скорее не согласен | −0,5 |
| Полностью не согласен | −1 |
| Не знаю / не уверен | вопрос пропускается |

Значение умножается на ключ утверждения: «+» = +1, «−» = −1. Получается позиция пользователя **u** по направлению утверждения. Пример: «полностью не согласен» с утверждением, у которого ключ «−», даёт u = +1.

## 2. Позиция списка по утверждению

- **Исходная позиция.** Берётся позиция списка P по направлению утверждения (`jef/positions/list_topic_positions.csv`, правила — SU п. 27.2–27.3).
- **Сжатие к нулю, если данных мало:**

  p = P × e / (e + K)

  - e — объём данных за позицией: число законопроектов кандидатов плюс 0,25 × число их голосов. Веса те же, что в самой позиции.
  - K = 2.
  - Позиция на 1–2 законопроектах ослабляется примерно вдвое, на 30 и больше — почти не меняется.

## 3. Близость

Косинусная близость по утверждениям, на которые пользователь ответил и по которым у списка есть позиция:

```latex
\text{близость} = \frac{\sum_i w_i\, u_i\, p_i}{\sqrt{\sum_i w_i u_i^2}\;\sqrt{\sum_i w_i p_i^2}}
```

- **Шкала.** От −1 (полностью противоположно) до +1 (полностью совпадает).
- **Почему косинус.** Он учитывает и знак, и силу позиции, но нормирует их. Поэтому список с крайними позициями не выигрывает автоматически. Без нормировки при случайных ответах чаще всех «побеждал» ХАДАШ (`local/research/positions_test/REPORT.md`, H7).
- **Вес w.** Обычно 1. Если на одно направление приходится два утверждения (пары «а/б»: 21, 40, 41, 55), каждое получает ½, чтобы направление не считалось дважды.
- **Покрытие.** Доля веса ответов, по которым у списка есть позиция.

## 4. Что показывается пользователю

1. **Оцениваемые списки по убыванию близости.** Пользователь видит топ-3, у каждого — число бывших депутатов, на которых держится позиция.
2. **Списки с предупреждением** (1 бывший депутат, SU п. 20) ранжируются вместе со всеми, но с пометкой «мало данных».
3. **Список с покрытием меньше 50 % ответов** не ранжируется и стоит ниже, с пометкой «позиция известна лишь по N % ответов» [А]. Пример: «Резервисты и экономика» (Хендель) — позиции есть лишь по 4 % утверждений.
4. **22 списка без бывших депутатов** показываются отдельной строкой «нет данных о работе в Кнессете», а не пропадают.

## 4а. Вопросы-размены [У, 2026-10-16]

Вместо прямого вопроса «что для вас важно» — до 5 вопросов о размене после основных ответов.
- **Пара.** Для каждого списка из текущего топ-5 по порядку берётся утверждение, которое больше всего добавило ему баллов (список с пользователем), и утверждение, которое больше всего сняло (список против пользователя). Утверждение используется не больше чем в одной паре.
- **Когда задаётся.** Только если удвоение веса одной из сторон меняет порядок топ-5. Если лучшая пара не меняет, пробуются следующие (до 3 с каждой стороны).
- **Вопрос.** «Сторона согласна с вами в теме А, но против вас в теме Б. Что для вас важнее: А, Б или одинаково?» Список не называется.
- **Вес.** Выбранная тема ×2 (конвенция Wahl-O-Mat и StemWijzer), вторая без изменений, «одинаково» ничего не меняет. Вес меняется у темы целиком, для всех списков.
- **Один вопрос на список.** Списки топ-5 перебираются по порядку, по каждому — не больше одного размена; поэтому вопросов от 0 до 5.
- **Порядок.** В опроснике (`quiz_cli.py`) размены задаются по одному, и условие «меняет топ-5» проверяется с уже выбранными весами. Лист для офлайн-пилота строит все пары сразу; на пилоте заказчика пары совпали.
- **Пилот.** `quiz_report.py` создаёт лист `tradeoffs_<файл ответов>.csv`; после заполнения столбца «Ответ» повторный запуск учитывает веса.

## 4в. Опросник в терминале [У, 2026-10-16]

`python3 pipeline/quiz_cli.py` — без интерфейса, флоу: старт → утверждения → вопросы-размены → таблица результатов → подробности по любому списку → обратно к таблице.
- **Утверждения:** 2 / 1 / 0 / -1 / -2 / нз; Enter — пропустить, `<` — назад, `q` — закончить ответы.
- **Таблица результатов:** все списки, а не топ; у каждого близость и пометка. Ниже — списки, которые не ранжируются, и списки без данных.
- **Подробности:** «почему подходит» и «почему не подходит» (по 5, `в` — все); номер утверждения открывает все законопроекты бывших депутатов списка по нему, разделённые на «в сторону вашего ответа» и «в противоположную».
- **Сессия** сохраняется в `jef/quiz/sessions/` (не в git: это ответы людей). `--answers <лист пилота или json сессии>` подставляет ответы.

## 4г. Как показывается результат [У, 2026-10-17]
- **Таблица:** место, список, близость, пометка (отношение к правительству не показывается [У 2026-10-17]). Числа бывших депутатов нет. Пометки двух типов: «мало депутатов: N» (статус warning) и «позиция известна лишь по N % ответов» (не ранжируется).
- **Подробности:** для каждого утверждения — заголовок, полный текст в том виде, как его видел пользователь, ваш ответ, сторона списка словами («за это утверждение» / «против этого утверждения», только по знаку, без чисел), основание (законопроекты бывших депутатов в вашу и в обратную сторону, голоса), вес ×2 после размена. Если законопроекты списка в основном в другую сторону, чем вывод, — пояснение, что позиция считается относительно среднего депутата.

## 5. Как выбрано K

Проверка на синтетических пользователях (`python3 pipeline/quiz_match.py --calibrate` → `jef/quiz/match_calibration.txt`).

**Персона.** Пользователь отвечает так, как продвигал бы законы список L:
- знак ответа — по позиции L;
- 20 % ответов перевёрнуты;
- 20 % ответов — «не знаю».

Проверяем, попадает ли L в топ-3.

**Нейтральность.** 500 пользователей со случайными ответами. Смотрим, какую наибольшую долю первых мест берёт один список. При полной нейтральности это 1/12 ≈ 0,083.

| K | Персона в топ-3 | Наибольшая доля первых мест (случайные ответы) |
|---|---|---|
| 0 | 0,99 | 0,128 |
| **2** | **0,98** | **0,102** |
| 5 | 0,98 | 0,108 |
| 10 | 0,98 | 0,112 |
| 20 | 0,98 | 0,118 |
| 50 | 0,96 | 0,124 |

- **Правило выбора:** наименьшая доля первых мест при условии, что персона попадает в топ-3 не реже 0,97. Это K = 2. Различия между K невелики: косинус сам убирает перекос в пользу крайних позиций.
- **Персона в топ-1** при K = 2 — 0,90 в среднем. Хуже всего у ЯХадут Тора (0,82) и РЦ (0,80): у них есть близкие соседи.

**Оговорка.** Персона построена из позиций самого списка, поэтому проверка показывает, что механика работает, а не что квиз точен для реальных людей. Это проверяется пилотом (H6).

## 6. Как пользоваться (пилот)

1. Заполнить столбец «Ответ» в копии `jef/quiz/pilot_answers.csv` (Google Sheets / Excel): 2, 1, 0, −1, −2 или «нз»; пустая ячейка — не отвечено. В таблице есть номер (1–60), тема и полный текст утверждения.
2. Запустить `python3 pipeline/quiz_match.py <файл ответов>`.
3. Пример со случайными ответами: `local/jef/quiz/pilot_answers_demo_random.csv`.

## 7. Ограничения

- Позиции относительные: «+» означает «продвигает сильнее среднего депутата» (METHOD_AUDIT, п. 9.2).
- Близость считается только по 60 утверждениям квиза. Слой «отношение к правительству» в неё не входит и показывается отдельно.
- Порог покрытия 50 % — решение исполнителя [А].
