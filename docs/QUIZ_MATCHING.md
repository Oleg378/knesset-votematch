# Как ответы пользователя превращаются в близость к спискам

_2026-10-17, обновлено 2026-10-18. Принято заказчиком [У]: косинусная близость; «не знаю» пропускается; вес утверждения 1/n на направление; сжатия нет (K = 0); результат — все ранжируемые списки по близости с двумя пометками, без числа бывших депутатов. Скрипт — `pipeline/quiz_match.py`. Аудит всей цепочки — `METHOD_AUDIT.md`._

## 1. Ответ → число

| Ответ | Значение |
|---|---|
| Полностью согласен | +1 |
| Скорее согласен | +0,5 |
| Нейтрально | 0 |
| Скорее не согласен | −0,5 |
| Полностью не согласен | −1 |
| Не знаю / не уверен | вопрос пропускается |

Значение умножается на ключ утверждения: «+» = +1, «−» = −1. Получается позиция пользователя **u** по направлению утверждения. Пример: «полностью не согласен» с утверждением, у которого ключ «−», даёт u = +1.

## 2. Позиция списка по утверждению

- **Исходная позиция.** Берётся позиция списка P по направлению утверждения (`jef/positions/list_topic_positions.csv`, правила — SU п. 27.2–27.3).
- **Сжатие к нулю, если данных мало:**

  p = P × e / (e + K)

  - e — объём данных за позицией: число законопроектов кандидатов плюс 0,25 × число их голосов (по частным законопроектам и по законопроектам чужого лагеря). Веса те же, что в самой позиции (P = A + 0,25·V + 0,25·O, 2026-10-18).
  - K = 0 [У] 2026-10-18: сжатия нет (см. «Правило выбора»).
  - При K = 0 p = P. Формула оставлена общей: K приходит в параметрах экспорта.

## 3. Близость

Косинусная близость по утверждениям, на которые пользователь ответил и по которым у списка есть позиция:

```latex
\text{близость} = \frac{\sum_i w_i\, u_i\, p_i}{\sqrt{\sum_i w_i u_i^2}\;\sqrt{\sum_i w_i p_i^2}}
```

- **Шкала.** От −1 (полностью противоположно) до +1 (полностью совпадает).
- **Почему косинус.** Он учитывает и знак, и силу позиции, но нормирует их. Поэтому список с крайними позициями не выигрывает автоматически. Без нормировки при случайных ответах чаще всех «побеждал» ХАДАШ (`local/research/positions_test/REPORT.md`, H7).
- **Вес w.** 1 / (число утверждений на направление). Если на одно направление приходятся два утверждения (бывшие пары «а/б»), каждое получает ½, чтобы направление не считалось дважды. С 2026-10-18 у каждого направления одно утверждение, поэтому w = 1; правило оставлено.
- **Покрытие.** Доля веса ответов, по которым у списка есть позиция.

## 4. Что показывается пользователю

1. **Оцениваемые списки по убыванию близости.** Показываются все ранжируемые списки; числа бывших депутатов нет [У 2026-10-17].
2. **Списки с предупреждением** (меньше 3 бывших депутатов в первой десятке списка, SU п. 20.2) ранжируются вместе со всеми, с пометкой «few former MKs: N».
2а. **Список с одним бывшим депутатом** не ранжируется [У 2026-10-18, внешний аудит С3]: при случайных ответах такие списки чаще всех выходили первыми. Показывается в блоке «Not ranked» с пометкой «few former MKs: 1» (`quiz_match.MIN_EX_MKS = 2`; одно правило `is_ranked` во всём коде).
3. **Список с покрытием меньше 50 % ответов** не ранжируется и стоит ниже, с пометкой «позиция известна лишь по N % ответов» [А]. Пример: «Резервисты и экономика» (Хендель) — позиции есть лишь по 4 % утверждений.
4. **22 списка без бывших депутатов** показываются отдельной строкой «нет данных о работе в Кнессете», а не пропадают.

## 4а. Вопросы-размены [У, 2026-10-16]

Вместо прямого вопроса «что для вас важно» — до 5 вопросов о размене после основных ответов.
- **Пара.** Для каждого списка из текущего топ-5 по порядку берётся утверждение, которое больше всего добавило ему баллов (список с пользователем), и утверждение, которое больше всего сняло (список против пользователя). Утверждение используется не больше чем в одной паре.
- **Когда задаётся.** Только если удвоение веса одной из сторон меняет порядок топ-5. Если лучшая пара не меняет, пробуются следующие (до 3 с каждой стороны).
- **Вопрос.** «Сторона согласна с вами в теме А, но против вас в теме Б. Что для вас важнее: А, Б или одинаково?» Список не называется.
- **Вес.** Выбранная тема ×2 (конвенция Wahl-O-Mat и StemWijzer), вторая без изменений, «одинаково» ничего не меняет. Вес меняется у темы целиком, для всех списков.
- **Один вопрос на список.** Списки топ-5 перебираются по порядку, по каждому — не больше одного размена; поэтому вопросов от 0 до 5.
- **Порядок.** В опроснике (`quiz_cli.py`) размены задаются по одному, и условие «меняет топ-5» проверяется с уже выбранными весами. Лист для офлайн-пилота строит все пары сразу; на пилоте заказчика пары совпали.
- **Пилот.** `quiz_report.py` создаёт лист `tradeoffs_<файл ответов>.csv`; после заполнения столбца «Ответ» повторный запуск учитывает веса.

## 4в. Опросник в терминале [У, 2026-10-16]

`python3 pipeline/quiz_cli.py` — без интерфейса, флоу: старт → утверждения → вопросы-размены → таблица результатов → подробности по любому списку → обратно к таблице.
- **Утверждения:** 2 / 1 / 0 / -1 / -2 / нз; Enter — пропустить, `<` — назад, `q` — закончить ответы.
- **Таблица результатов:** все списки, а не топ; у каждого близость и пометка. Ниже — списки, которые не ранжируются, и списки без данных.
- **Подробности:** «почему подходит» и «почему не подходит» (по 5, `в` — все); номер утверждения открывает все законопроекты бывших депутатов списка по нему, разделённые на «в сторону вашего ответа» и «в противоположную».
- **Сессия** сохраняется в `jef/quiz/sessions/` (не в git: это ответы людей). `--answers <лист пилота или json сессии>` подставляет ответы.

## 4г. Как показывается результат [У, 2026-10-17]
- **Таблица:** место, список, близость, пометка (отношение к правительству не показывается [У 2026-10-17]). Числа бывших депутатов нет. Пометки двух типов: «мало депутатов: N» (статус warning) и «позиция известна лишь по N % ответов» (не ранжируется).
- **Подробности:** для каждого утверждения — заголовок, полный текст в том виде, как его видел пользователь, ваш ответ, что показывают действия бывших депутатов списка («points toward / against this statement» / «shows no clear position», только по знаку, без чисел; [У] 2026-10-18 — говорим об измеренном, а не «список за утверждение»; при «toward» — оговорка, что цена «even if…» данными не измеряется), основание (законопроекты бывших депутатов в вашу и в обратную сторону, голоса), вес ×2 после размена. Если сторону списка дали голоса, а не его законопроекты (законопроектов нет или они в другую сторону), — пояснение об этом. Формулировки — `export/V2_HANDOFF.md`, п. 3.

## 5. Как выбрано K

Проверка на синтетических пользователях (`python3 pipeline/quiz_match.py --calibrate` → `jef/quiz/match_calibration.txt`).

_Таблица ниже — исторический прогон 2026-10-17 (авторство ещё центрировалось); текущий вывод `--calibrate` — `jef/quiz/match_calibration.txt`, решение K = 0 принято 2026-10-18._

**Персона.** Пользователь отвечает так, как продвигал бы законы список L:
- знак ответа — по позиции L;
- 20 % ответов перевёрнуты;
- 20 % ответов — «не знаю».

Проверяем, попадает ли L в топ-3.

**Нейтральность.** 500 пользователей со случайными ответами. Смотрим, какую наибольшую долю первых мест берёт один список. При полной нейтральности это 1/12 ≈ 0,083.

| K | Персона в топ-3 | Наибольшая доля первых мест (случайные ответы) |
|---|---|---|
| 0 | 0,99 | 0,128 |
| **2** | **0,98** | **0,102** |
| 5 | 0,98 | 0,108 |
| 10 | 0,98 | 0,112 |
| 20 | 0,98 | 0,118 |
| 50 | 0,96 | 0,124 |

- **Правило выбора:** наименьшая доля первых мест при условии, что персона попадает в топ-3 не реже 0,97. Это K = 2. [У] 2026-10-18: критерий «доля первых мест при случайных ответах» убран — она зависит от кластеров списков (у списка без близких соседей выше), а не от K. По узнаванию персоны (своё место 1-е: K = 0 — 0,80, K = 2 — 0,78, K = 10 — 0,72) и по тесту между созывами лучше всего K = 0. **Принято K = 0: сжатия нет.** Различия между K невелики: косинус сам убирает перекос в пользу крайних позиций.
- **Персона в топ-1** (17.10, до отмены центрирования) при K = 2 — 0,90 в среднем. Хуже всего у ЯХадут Тора (0,82) и РЦ (0,80): у них есть близкие соседи.

**Оговорка.** Персона построена из позиций самого списка, поэтому проверка показывает, что механика работает, а не что квиз точен для реальных людей. Это проверяется пилотом (H6).

## 7. Ограничения

- Авторство не центрируется: «+» значит, что бывшие депутаты списка вносили законопроекты в эту сторону; часть от голосов (V) — относительная, после вычета линии «правительство — оппозиция». Поэтому позиция, совпадающая с линией коалиции, в голосах почти не видна (известное ограничение, METHOD_AUDIT п. 9).
- Близость считается по утверждениям квиза (78 на 2026-10-18). Слой «отношение к правительству» в неё не входит и не показывается [У 2026-10-17].
- Порог покрытия 50 % — решение исполнителя [А].
- **CLOSE = 0,3** [У 2026-10-18]: «нет явной позиции» ниже 0,3; правило — наименьшая граница, выше которой сторона совпадает между созывами ≥ 75 %.
- **Шкала ответов [У 2026-10-18, Р11].** Близость — косинус: если все ответы «полностью согласен», результат тот же, что при «согласен»; сила ответа важна только в смешанных ответах. Описывается в FAQ.
- **Лидеры с малым числом своих законопроектов [У 2026-10-18, Р10]** (у министров и глав правительства их почти нет): позиция списка держится на остальных бывших депутатах и на голосах. Объясняется на странице методологии, пометки в результатах нет.
- **Перешедшие в другой список [У 2026-10-18, Р9]:** история депутата идёт в его новый список 2026 (человек тот же, голосовал сам). Объясняется на странице методологии.

## Порядок вопросов: ядро → уточняющие → «что важнее» (2026-10-18)

Идея заказчика [У]: не задавать все утверждения, а сначала общие, потом уточняющие, потом выбор «что важнее». Числа 8 + 7 + 5, граница повтора 0,7 и доля оси правительства в ядре — [У]; выбор уточняющих (4 ближайших списка) — [А]. Код — `pipeline/quiz_flow.py`, все числа — в `FLOW` (их же получит экспорт v2, фронт читает оттуда). Сейчас **8 + 7 + до 5** [У] 2026-10-18; например 5 + 10 + 2 — это `core: 5, clarify: 10, trade: 2`. Есть и правило остановки (`stop_gap`, `min_questions`, `max_questions`; выключено).
- **Почему 8 + 7 (симуляция, `local/research/scripts/flow_*.py`).** Синтетический избиратель списка отвечает по позициям списка, 20 % «не знаю», 10 % или 20 % ответов против своего списка. Цель — свой список 1-й при ответах на все вопросы: 0,98 / 0,89 (шум 10 % / 20 %). Узнавание растёт с числом вопросов без резкого перегиба; плато при шуме 10 % — после ~25 вопросов. Уточняющие дают +7–9 пунктов к тому же числу общих вопросов, когда ядро 5–9, и +2–3 при ядре от 12; при одной длине разбиение внутри «ядро 5–10» почти не важно. 8 + 7: 1-й 0,81, топ-3 0,94 (шум 10 %); 0,63 / 0,81 (шум 20 %). «Что важнее» добавляют 3–5 пунктов.

- **Ядро (одинаковое для всех).** Утверждения, по которым оцениваемые списки различаются сильнее всего: SD позиций списков × доля списков, у которых позиция есть. Ограничения: не однополярное — у списков с явной позицией (|p| ≥ 0,2) есть обе стороны [У 2026-10-18, внешний аудит К2]; одно утверждение на направление; не повторяет порядок списков уже выбранного (|r| < 0,7) [У] 2026-10-18 — при 0,8 четыре из восьми вопросов стояли на одной оси (судебная реформа / правительство); сравнивались 0,8, 0,7 и «разброс × уникальность» (`local/research/scripts/core_diverse.py`, `core_stability.py`): при 0,7 ядро узнаёт свой список лучше (0,66 против 0,60), итог 8 + 7 тот же, устойчивость средняя; не больше половины ядра на оси правительства — 2 из 5, 3 из 6 (`core_gov_share`) [У] 2026-10-18.
- **Уточняющие (после каждого ответа).** Берутся 4 ближайших к пользователю списка по текущим ответам; задаётся ещё не показанное утверждение, по которому они различаются сильнее всего (SD их позиций).
- **«Что важнее».** Без изменений (п. 4), не больше `trade`.
- **«Ответить ещё».** После результатов уточняющие вопросы продолжаются, пока не кончится пул.
- Близость считается так же, по всем данным ответам. Терминальный квиз: `python3 pipeline/quiz_cli.py` (новый порядок), `--all` — все утверждения подряд.
