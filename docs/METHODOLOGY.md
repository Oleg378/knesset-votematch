# Методология

_Концепция верхнего уровня: что мы делаем и каких принципов придерживаемся. Термины и действующие правила — [SHARED_UNDERSTANDING.md](SHARED_UNDERSTANDING.md); реализация и числа — [TECHNICAL.md](TECHNICAL.md); тексты для пользователя на сайте — `export/quiz_texts.json` (контракт `export/WEB_CONTRACT.md` § 7). Решение, которое противоречит этому документу, не принимается без изменения самого документа заказчиком._

## 1. Что делаем

Квиз сопоставляет взгляды пользователя с позициями списков на выборах в Кнессет 26-го созыва (27.10.2026). Позиция списка определяется по **прошлым действиям его кандидатов в Кнессете 24–25 созывов**.

## 2. Модель: три части, которые определяются независимо

1. **Законопроект** — намерение изменить существующее положение. Мы определяем, **что** он меняет (темы, их может быть несколько) и **в какую сторону** по каждой теме.
2. **Действия:** что каждый депутат сделал в отношении каждого законопроекта.
3. **Позиция партии** складывается из связок «законопроект — действие — депутат — партия».

## 3. Принципы

1. **Только официальные источники:** данные Кнессета, «Решумот», Центральная избирательная комиссия. Сторонние источники — только для сверки.
2. **Только действия в Кнессете.** Программы и заявления партий не используются.
3. **Единообразие (P0):** одни и те же правила для всех тем, партий и фракций, без исключений. Если где-то плохая точность, ищем универсальное правило, а не заплатку.
4. **Агент не решает сам (P1):** при любой неоднозначности ИИ-агент останавливается, даёт варианты и спрашивает заказчика. Всё, что агент придумал сам, остаётся предложением, пока заказчик его не утвердил.
5. **Важность темы не определяется числом законопроектов.** Редкие темы важны не меньше частых.
6. **Проверяемость:** каждое решение записано вместе со статусом; качество меряется независимыми замерами.
7. **Честность о покрытии:** у списка без истории в Кнессете оценки нет, вместо неё дисклеймер; если история тонкая, оценка идёт с предупреждением.

## 4. Чего не делаем

1. Не задаём заранее большие идеологические оси. Если они понадобятся, выводим их в конце из данных.
2. Не формулируем вопросы под пользователя, пока определяем позиции.

## 5. Ограничения (заявляем открыто)

Квиз — ориентир, а не точное измерение. Мы прямо говорим пользователю, где метод даёт шум и погрешность (измеренный масштаб — TECHNICAL.md, разделы 7 и 12; текст для сайта — раздел `methodology` в `export/quiz_texts.json`).

1. **Только действия бывших депутатов в Кнессете 24–25.** Новые кандидаты, программы и заявления не видны; список без бывших депутатов не оценивается, с одним — не ранжируется. Позиция объединённого списка — история его партий-участниц, и она может быть историей в основном одной из них.
2. **Голоса — отчасти дисциплина лагеря.** Почти все голосования идут по линии блока; голоса считаются с меньшим весом, чем собственные законопроекты, и одинаково для обоих лагерей. Голос «против» может означать обратное знаку темы (против закона как слишком мягкого) — метод причину голоса не видит.
3. **Продвигающая сторона слышнее блокирующей.** Кто вносил законопроекты по теме, получает сильную позицию; кто только голосовал против — слабую. Это осознанный выбор: «не вносил» не значит «против».
4. **У лидеров и министров мало собственных законопроектов** — позиция списка держится на остальных его бывших депутатах и на голосах.
5. **Разметку законопроектов делала языковая модель,** исправления — тоже модели, по правилу двух независимых проверок. Точечные ошибки остаются.
6. **Проверки делали модели, а не люди.** Числа согласия — согласованность моделей между собой, не измеренная точность для избирателей; ни одна позиция списка не подтверждена человеком, знающим Кнессет.
7. **Мало списков — шумная статистика.** На 12 списках пороги отбора — заранее заданные границы правил, а не измерения; близкие по значению списки статистически не различаются, поэтому близость показывается округлённой.
8. **«Цена» в утверждении («даже если…») данными не измеряется.**
9. **Темы отбираются там, где списки различаются в данных,** а не по значимости для избирателя; значимые темы вне квиза и причины названы на сайте.
10. **При случайных или сплошь нейтральных ответах** чаще выходят первыми списки «с краю» облака — свойство метода «ближайший список»; для осмысленных ответов не проявляется.

## 6. Как метод будет проверяться дальше

После выборов — проверка на людях по протоколу `VALIDATION_PROTOCOL.md`: доля избирателей, получивших свой список первым и в тройке, устойчивость повторного прохождения, оценка позиций экспертами. Протокол и метрики записываются до сбора данных и не меняются по его итогам.
