# Общее понимание (рабочий документ)

_Контракт между заказчиком и агентом: термины, действующие правила и открытые вопросы — без истории, чисел и обоснований. Концепция — [METHODOLOGY.md](METHODOLOGY.md); реализация и числа — [TECHNICAL.md](TECHNICAL.md); ход работы — [WORKLOG.md](WORKLOG.md); журнал прежних решений — [archive/DECISIONS_LOG.md](archive/DECISIONS_LOG.md). На пункты ссылаемся по номеру («SU п. 12»); номера стабильны._

**Метки статуса:**

- **[У]** — утверждено заказчиком;
- **[А]** — предложение агента: внедрено, но заказчиком явно не утверждено, считается предварительным (принцип P1);
- **[О]** — открытый вопрос;
- **[Ф]** — факт из данных.

## A. Модель

1. **Законопроект** — **[У]** намерение изменить существующее положение.
2. **Тема** — **[У] что меняется** (объект изменения). У законопроекта может быть несколько тем.
3. **Направление** — **[У]** величина, которую закон может увеличить или уменьшить. У направления нейтральное название и определены «+» и «−». Пример: «полномочия судебной системы», «социальные выплаты», «права иностранцев на въезд и пребывание». Один закон может двигать несколько направлений. Тема и направление — одно понятие (п. 23).
4. **Прямые действия** — **[У]** действия депутата в отношении законопроекта, записанные в официальных данных Кнессета (OData v4). Список зафиксирован:
   - **4.1. Внесение законопроекта** — `KNS_BillInitiator`, `IsInitiator = true`.
   - **4.2. Присоединение к законопроекту** (מצטרף) — `KNS_BillInitiator`, `IsInitiator = false`.
   - **4.3. Отзыв подписи** (חזר בו) — `KNS_BillHistoryInitiator`, причина «חזר בו».
   - **4.4. Голосование «за»** — `KNS_PlenumVoteResult`, `ResultCode = 7`.
   - **4.5. Голосование «против»** — `ResultCode = 8`.
   - **4.6. Воздержался** — `ResultCode = 9`.
   - **4.7. Присутствовал, не голосовал** — `ResultCode = 6`.
5. **[У] Каждое действие — факт.** Значений внутри типа нет: «за» и «против» — разные действия.
6. **Вычисляемые действия** — **[У]** производные: их нет в данных напрямую, они вычисляются из прямых действий (п. 4) и контекста. Правила — п. 34.
   - **6.1. Отсутствие на голосовании:** депутат по составу Кнессета был, а строки результата нет.
   - **6.2. Бойкот:** массовое отсутствие одного блока на голосовании (порог — п. 14.3). Это действие группы, а не одного депутата.
   - **6.3. Блокировка — не вычисляется и метрикой не является [У].**
7. **Позиция** — **[У]** строится из прямых действий (п. 4); отсутствия и бойкот (п. 6) в позицию не входят. Правило — п. 34.

## B. Данные

8. **Источники.**
   - **8.1. Данные Кнессета** — OData v4. **[Ф]** Старый сервис `Votes.svc` (v2) остановился на 2021 году, 25-го созыва в нём нет.
   - **8.2. Списки 2026** — **[У]** страницы Центральной избирательной комиссии, читаются через браузер заказчика (сессия с `--chrome`, только чтение).
   - **8.3. Сторонние агрегаторы** — **[У]** только для сверки.
9. **Охват** — **[У]**:
   - **9.1.** созывы 24 и 25;
   - **9.2.** голосования всех чтений.
10. **Какие голосования используются.**
    - **10.1. Тип и этап [А]:** каждое голосование относится к типу (законопроект, поправка, процедурное и т. д.) и этапу чтения.
    - **10.2. Смысл «за» [А]:** в голосовании по законопроекту «за» означает «за законопроект». Исход — «принят», если «за» больше, чем «против».
    - **10.3. Поправки (הסתייגויות) не используются [А]:** «за» в них означает «за поправку», а не «за законопроект».
    - **10.4. Роспуск Кнессета [А]** — голосование о власти, а не о политике.
    - **10.5. Тайные голосования и голосования поднятием рук не используются [А]:** в них нет поимённых «за» и «против».
    - **10.6. Голосования по линии блока не выбрасываются [У]:** как учитывать дисциплину, решается через данные.
11. **Очистка данных** — **[А]** удаление дублей, локальная дата, листание по ключу, 2 потока, ближайший интервал фракции для 11 голосов без фракции, созыв по дате. Подробно — в TECHNICAL.md.

## C. Фракции и блоки

12. **Фракция** — официальная парламентская группа в данных Кнессета.
13. **Блок** — **[У]** два понятия: «правительство» — фракция, у которой есть министры или заместители министров (официальные должности, по датам); «лагерь» для очистки голосов и для сигналов O и G (п. 34) — правительство по министрам **или** фракция без министров, голосующая с большинством правительства в ≥ 90 % случаев в созыве.
14. **Признаки голосования** — описывают голосование целиком. Пороги **[У] «ок»**:
    - **14.1. Сплочённость блока:** 0,9.
    - **14.2. Низкая явка:** меньше 25 присутствующих.
    - **14.3. Бойкот:** участие одного блока < 0,1 при участии другого ≥ 0,4.
    - **14.4. Несогласная фракция:** от 2 голосов против линии своего блока.
    - **14.5. [А]** Воздержавшиеся и неголосовавшие (п. 4.6, 4.7) в признаках и в позиции не учитываются.

## D. Списки 2026 и кандидаты

15. **Список (2026)** — то, что стоит в бюллетене. Чаще всего это объединение нескольких партий.
16. **Кандидат** — человек в списке 2026. Если он был депутатом 24–25 созывов, у него есть история действий.
17. **Позиция списка** — **[У]** считается **через людей**: через кандидатов, которые были депутатами, а не через фракции.
18. **Совпадение кандидата с депутатом** — **[А]** фамилия стоит в начале имени в записи комиссии и совпадает одно из имён. Уменьшительные имена и однофамильцы разбираются вручную.
19. **Вес кандидата по месту в списке** — **[У]** равный (тест между созывами вес по месту не обосновал); почётные места в конце списка весят наравне.
20. **Покрытие** — **[У]**:
    - **20.1.** Список без бывших депутатов не оценивается и получает дисклеймер.
    - **20.2.** Меньше 3 бывших депутатов в первой десятке — оценка с предупреждением.
    - **20.3.** Список с одним бывшим депутатом показывается, но не ранжируется.

## E. Разметка и проверка

21. **Разметка** — **[У]** массовая — языковой моделью (Jev, затем Sonnet для распределения по частям и Opus для суждений), малые объёмы — агент; метки меняются только по правилам проверки (п. 37).
22. **Проверка** — **[У]**:
    - **22.1.** Вопрос модели с допущением задаётся вместе с проверкой этого допущения.
    - **22.2.** Выборки для оценки строятся по ответам модели.
    - **22.3.** «Нейтрально» и «неприменимо» — разные ответы.
    - **22.4.** Независимый замер повторяется после каждого заметного изменения.
23a. **Бюджетные пакеты** (חוק ההסדרים) — **[У]** статьи пакета размечаются по тексту статьи (агентом, а не Jev — сознательное исключение); голосование за пакет целиком несёт главные темы его статей; в позицию голоса по пакетам не входят (п. 34).
23c. **Зимнее время** — **[У]** 2026-10-13: законопроекты о зимнем времени (חוק קביעת הזמן, 8 шт.) — технические, не учитываются; список — `jef/directions/labels/overrides.json`.
23b. **Голосования по одному закону в разных чтениях и по статьям** — **[У]** 2026-10-13: учитываются все (первое, второе по статьям, третье). Это не дубли, а последовательная позиция депутата: считаются все действия в Кнессете.

## F. Действующие правила

_Одна строка на правило; подробности и числа — TECHNICAL.md, процедуры — `.claude/skills/`._

23. **[У]** Тема = направление: одно понятие; у темы нейтральное название и определённые «+» и «−».
24. **[У]** Минимального охвата у темы нет: редкие темы важны не меньше частых.
25. **[У]** Источник разметки — название и пояснительная записка законопроекта (статьи пакетов — текст статьи); проверки — на записке.
26. **[У]** Инструменты: Opus — суждения и тексты, Sonnet — массовое распределение; условие замены модели — качество не ниже прежней на эталоне.
27. **[У]** Логика «действия → позиция» — п. 34–36.
28. **[О]** Пересмотр решений агента с меткой [А].
29. **[У]** Ручного разбора законопроектов нет; метки правятся только проверкой (п. 37).
30. **[У]** История депутата идёт с ним в список 2026; переходы с прессой не сверяются; партия-участница списка берётся из данных ЦИК.
31. **[У]** Правительственные законопроекты входят только голосами (O и G, п. 34); бюджетные пакеты — никому.
32. **[У]** Проверки людьми не проводятся; заявлено пользователю как ограничение.
33. **[У]** Единица вопроса — тема; законопроекты показываются в разборе.
34. **Позиция депутата по теме [У]:** P = A + 0,25·V + 0,25·O + 0,25·G. A — средний знак внесённых им законопроектов по теме, не центрируется (не вносил — 0); V — голоса по частным законопроектам своего лагеря за вычетом оси «правительство — оппозиция»; O — голоса по законопроектам чужого лагеря; G — голоса коалиции по собственным правительственным законопроектам; отсутствующая компонента — 0; созывы объединяются; веса подобраны по устойчивости между созывами и заморожены.
35. **Позиция списка [У]:** среднее по его кандидатам — бывшим депутатам с действием по теме, равные веса (п. 19); покрытие — п. 20.
36. **Явная позиция [У]:** |p| ≥ 0,2, не меньше 2 депутатов и 2 разных законопроектов; иначе «нет явной позиции».
37. **Проверка меток [У]:** метка снимается при двух слепых «не про вопрос» (спорное — третья проверка, большинство); знак меняется только при согласии проверки на полной записке; метка добавляется при двух слепых «про вопрос» с одним знаком. Проверяющий не видит нашей метки.
38. **Темы без своего вопроса [У]:** дубль по числу (> 50 % названий в теме действующего вопроса) или по смыслу (слепая проверка «тот же вопрос для избирателя») → законопроекты проверяются на добавление в тему вопроса; вложенные пары — стратегия 1 (узкая остаётся, общее вычитается из широкой) или 2 (узкая исчезает) по смыслу, с ограничениями (а)/(б); корзины делятся на части; остатки разделённых и технические темы — без вопроса. Каждая проходящая отбор тема имеет вопрос или решение в реестре.
39. **Отбор темы в квиз [У], пороги заморожены:** ≥ 8 оцениваемых списков с ≥ 3 депутатами по теме, разброс позиций ≥ 0,25, ≥ 5 разных названий законопроектов. Вопрос, потерявший порог, снимается с уведомлением заказчика.
40. **Утверждения [У]:** правила — `jef/quiz/GUIDELINES.md`; одно утверждение на тему; текст меняется только через стандартный аудит и апрув заказчика; номера стабильны; дубли по смыслу — слепая проверка, при равенстве остаётся существующий.
41. **Сопоставление [У]:** косинус по отвеченным утверждениям; «не знаю» пропускается; вес 1/n на тему; сжатия нет (K = 0); покрытие ≥ 50 % ответов; результат — все ранжируемые списки по близости.
42. **Порядок вопросов [У]:** 8 общих (маркеры главных осей различий между списками × интерес², одна область, не два из группы похожести) → 7 уточняющих по одному (утверждение, лучше всего разводящее лидера и претендентов × интерес², только с явными позициями на обеих сторонах среди 4 ближайших, не область предыдущего, не из группы похожести) → до 5 разменов «что важнее» (×2, только если меняет топ-5) → «ответить ещё». Метаданные утверждений (интерес, область, группа похожести — слепые оценки агентов) влияют только на порядок.
43. **Что показывается [У]:** все ранжируемые списки с близостью (один знак после запятой) и двумя пометками («мало депутатов: N», «позиция известна по N % ответов»); не ранжируемые — отдельно; разбор по утверждению — законопроекты (иврит) и голоса, с подписью, когда сторона дана голосами. Не показываются: отношение к правительству, число депутатов, логотипы. Ответы пользователя нигде не хранятся. Состав списка по партиям-участницам — в экспорте; показ — отдельное решение.
44. **Язык [У]:** продукт — английский; законопроекты — иврит без перевода; списки — английские названия ЦИК; имена — транслитерация из ручной таблицы; русский — рабочий.
45. **Осознанные допущения, заявленные пользователю [У]:** сторона, продвигающая изменение, слышна громче блокирующей (1 : 0,25); голоса — отчасти дисциплина лагеря; темы выбраны там, где списки различаются, а не по значимости; при случайных ответах краевые списки выигрывают чаще (геометрия); голос против может означать обратное знаку; проверки — только моделями. Тексты — `export/METHODOLOGY_PAGE.md`.
46. **Право оспорить [У]:** публичная таблица позиций списков с законопроектами; обращения — GitHub issues репозитория.
47. **Агентная работа [У]:** задания вслепую (без наших меток и позиций), два независимых агента, расхождения — третий; вывод агента — не решение заказчика; песочница `local/` и ответы людей в репозиторий не попадают.
