## Как читать

**Статусы решений:**

- **Принято**: решение внедрено, данные его подтверждают, пересматривать не планируем.
- **Предварительно**: разумное значение по умолчанию, внедрено. Пересмотрим, когда будут результаты на реальных данных (обычно это пороги).
- **Открыто**: решения пока нет, указано, от чего оно зависит.

**Префиксы идентификаторов:** S — источники, N — очистка и нормализация, B — блоки, V — классификация голосований, A — вычисляемые признаки, F — отбор, Q — модель квиза.

## Принцип единообразия (P0)

_Введён 2026-10-11 по замечанию заказчика._

Правила обработки одинаковы для всех тем, партий и фракций. **Исключений под конкретную тему или фракцию нет.** Если на каком-то участке точность плохая, мы ищем универсальное правило, которое улучшает результат везде, а не заплатку для одной темы. Различия между темами допустимы только в двух местах:

1. **Содержание шкалы или описания темы.** Оно должно описывать тот спор, о котором законопроекты. Механика при этом общая для всех: одни и те же уровни, одна и та же «развилка» (её может получить любая шкала).
2. **Сами данные:** уверенность модели, согласие сигналов между собой, голоса.

Решения, которые ссылаются на конкретную тему или фракцию, принимаются только как результат общего правила, применённого к данным. Пример — блоки (B0): правило одно для всех, а по фракциям расходятся только данные.

## Принцип: ИИ-агент не решает сам при неоднозначности (P1)

_Введён 2026-10-12 по решению заказчика._

ИИ-агент (Claude и любые запущенные им сессии) не принимает решений самостоятельно, если есть неоднозначность: несколько разумных вариантов, порог или параметр без обоснования в данных, выбор, влияющий на результат или методику. В таком случае агент **останавливается и спрашивает заказчика**, как поступить, и перечисляет варианты с последствиями. Заранее выбранный вариант агент не продвигает как готовый план.

- Самостоятельно агент делает только однозначные вещи: техническую реализацию уже принятого решения, исправление явных ошибок, проверки.
- Всё, что агент придумал сам (порог, критерий, список, формулировка шкалы), помечается как «предложение агента» и не считается принятым решением, пока заказчик его не подтвердил.
- Решения, принятые агентом самостоятельно до введения P1, считаются предварительными; их перечень и пересмотр — отдельной задачей.

                                        ▼

Единица хранения — **голос депутата** (`vote_results`). Позиции фракций, блоков и партий из него только вычисляются и нигде не хранятся как исходные факты. В этом гипотеза подтвердилась.

## Определения вычисляемых признаков

| Признак | Уровень | Определение |
| --- | --- | --- |
| `vote_roster` | депутат × голосование | Все депутаты на дату голосования, интервалы полуоткрытые `[начало, конец)`. Отсутствующие: `result IS NULL` |
| `n_for`, `n_against`, `n_abstain` | голосование | Число голосов «за», «против», «воздержался» |
| `n_present` | голосование | Все строки результата, включая «присутствовал, не голосовал» |
| `p_for` | фракция | `за / (за + против)`. Воздержавшиеся и неголосовавшие в знаменатель не входят (A6) |
| `participation` | фракция, блок | `присутствовали / состав на дату` |
| `cohesion` | блок | `max(за, против) / (за + против)` |
| `direction` | блок | «за», если `за > против`; «против», если меньше; при равенстве NULL |
| `accepted` | голосование | `n_for > n_against` (V4) |
| `participation_pattern` | голосование | `one_bloc_absent`: участие одного блока меньше 0,1, другого не меньше 0,4. `low_turnout`: присутствуют меньше 25. Иначе `normal` (A2, A3) |
| `split_pattern` | голосование | См. таблицу ниже (A1) |
| `dissenting_factions` | голосование | Фракции коалиции или оппозиции с минимум 2 голосами «за»/«против», большинство которых пошло против направления своего блока (A4) |
| `pivotal_factions` | голосование | Фракции, которые одни, проголосовав иначе, изменили бы исход (A5) |

Значения `split_pattern`, проверяются по порядку:

| Значение | Условие | Смысл |
| --- | --- | --- |
| `no_blocs` | ни у коалиции, ни у оппозиции нет голосующих | период межвластия (B4) |
| `one_bloc_only` | у одного из блоков меньше 3 голосующих | бойкот или почти пустой зал |
| `consensus` | направления блоков совпадают, оба со сплочённостью от 0,9 | все согласны, для квиза неинформативно |
| `cross_bloc_majority` | направления блоков совпадают, но хотя бы один блок расколот | большинство обоих блоков и несогласное меньшинство (пример: UNRWA) |
| `bloc_line` | направления разные, оба блока со сплочённостью от 0,9 | голосование по коалиционной дисциплине |
| `bloc_line_with_dissent` | направления разные, хотя бы один блок расколот | кто-то пошёл против своего блока |

### A. Пороги вычисляемых признаков

| ID | Решение | Обоснование | Статус |
| --- | --- | --- | --- |
| A1 | Блок «сплочённый», если `cohesion` не меньше 0,9 | Обычная практика для партийной дисциплины. Проверим чувствительность (0,85 / 0,95) | Предварительно |
| A2 | `low_turnout`, если присутствуют меньше 25 | Отсекает пустые голосования второго чтения по статьям. К предварительному чтению фильтр не применяется: там малая явка — норма | Предварительно |
| A3 | `one_bloc_absent`: участие одного блока меньше 0,1, другого не меньше 0,4 | На примере закона о разумности: участие оппозиции 0, коалиции 1,0 | Предварительно |
| A4 | Фракция считается несогласной только при минимум 2 голосах | Один депутат — это личная позиция, а не позиция фракции | Предварительно |
| A5 | `pivotal_factions` не используется сам по себе, только вместе с `dissenting_factions` | При разрыве в 8 голосов решающей оказывается любая фракция, у которой против 5 и больше депутатов, поэтому на блоковых голосованиях признак бессмыслен | Принято |
| A6 | В `p_for` воздержавшиеся и «не голосовал» не входят | Воздержание — отдельный сигнал, учтём в весах (Q4) | Предварительно |

### Q. Модель квиза

| ID | Решение | Обоснование | Статус |
| --- | --- | --- | --- |
| Q1 | Вопрос квиза строится вокруг **законопроекта**, позиция партии сводится из трёх сигналов: инициатива, блокировка, голосования | Решение заказчика. Инициатива покрывает в 4–6 раз больше законопроектов, чем голосования, и не искажена дисциплиной | Принято |
| Q2 | Депутат → партия 2026 через ручной справочник `faction → party_2026` | Фракции раскалываются и переименовываются: «Национальное единство» → «Кахоль Лаван – Национальное единство», «Ямина» → «Ямина»/«Новая правая» и т. д. | Открыто (нужен список партий 2026) |
| Q3 | Трактовка бойкота в матче | Варианты: «против» или отдельное значение. Бойкот различим в данных (`one_bloc_absent`) | Открыто |
| Q4 | Веса сигналов задаются в конфиге и проверяются тремя тестами: партия как пользователь, предсказательная сила сигнала, устойчивость к ±30 % | Веса частично ценностный выбор, поэтому они должны быть прозрачными и проверяемыми | Открыто |
| Q5 | Адаптивный подбор вопросов считается в браузере по матрице «партия × вопрос», дерево заранее не строится | Дерево на 3 варианта ответа и глубину 10 — десятки тысяч узлов, а матрица весит десятки килобайт | Предварительно |

## Допущения и известные ограничения

| # | Ограничение | Последствие | Как обходим |
| --- | --- | --- | --- |
| L1 | Даты внесения частных законопроектов нет: `PublicationDate` пуста у 98 % | Нельзя точно определить фракцию инициатора на момент внесения | Фракция определяется в пределах созыва, неоднозначность снимает справочник Q2 |
| L2 | В `KNS_Bill` только текущий статус, истории нет | Нельзя напрямую узнать, на каком этапе законопроект застрял | Восстанавливаем по датам голосований и заседаний комиссий |
| L3 | Решений Министерского комитета по законодательству в OData нет | Основная блокировка частных законопроектов невидима | В данных видно только её следствие: голосование коалиции «против» на предварительном чтении |
| L4 | Поимённых голосований в комиссиях нет | Блокировку в комиссии видно только косвенно (заморозка) | Председатель комиссии и время с последнего обсуждения |
| L5 | `IsContinuationBill` пуст | Законопроекты, перенесённые из прошлых созывов, не отмечены | Определяем по `ForOptionID` 9 и по Id законопроекта из старого диапазона (пример: 1046280) |
| L6 | В дни ротаций в составе 121 депутат (9 голосований), у 4 строк состава не определён блок | Пренебрежимо мало | Оставлено как есть |
| L7 | Особое большинство для основных законов (61) не проверяется | Исход может быть неточным для отдельных статей основных законов | Поставлен флаг `is_basic_law`. На третьих чтениях расхождений со статусом нет |

## Как менять решения

1. Поменять ручную таблицу в `manual/` или правило в `build/*.sql`. В комментарии к правке указать ID решения.
2. Пересобрать базу: `python3 build/build.py`.
3. Обновить строку в этом реестре: решение, обоснование, статус. Если решение заменяется, старое не удалять, а пометить «Заменено → новый ID».
4. Если меняются цифры, обновить их в [report.md](report.md).
