# Гипотеза: атрибуция голосований Кнессета для квиза

_Черновик методологии, 2026-10-10. Факты в примерах по памяти, их нужно сверить через Votes.svc._

## Гипотеза

Голосования нельзя использовать в квизе как есть. Каждому голосованию нужен набор атрибутов. Большая часть этих атрибутов **вычисляется из голосов депутатов**, а ручная работа нужна только для небольшого числа признаков и только на отобранных голосованиях (сотни, а не тысячи).

## Основа: атом — голос депутата

Позиция партии хранится не как факт, а как производная: агрегат голосов её депутатов по выбранному правилу сопоставления «депутат → партия».

```
голос депутата (атом, хранится всегда)
   → правило сопоставления депутат → партия (явный выбор, версионируется)
      → позиция партии по голосованию: p_for, cohesion, n_present (вычисляется)
         → матрица партии × голосования для матча и кластеризации
```

Почему атом именно голос депутата:

1. Партии нестабильны: расколы, слияния, переименования, переходы депутатов. Голос депутата неизменен.
2. Сопоставить голос с партией можно по-разному: по фракции на дату голосования или по нынешнему списку. Это методологический выбор, и через атомы его можно сделать явно.
3. Позицию новых партий без истории голосований можно посчитать по голосам их кандидатов, если те были депутатами.
4. Раскол внутри партии (`cohesion`) виден только при агрегации снизу.
5. Можно показать пользователю депутата, который голосовал ближе всего к нему.

## Примеры, которые проверяют гипотезу

Каждый пример ломает какое-то наивное правило.

### 1. Поправка об отмене принципа разумности (июль 2023)

Часть судебной реформы. Принята голосами коалиции при бойкоте оппозиции, в январе 2024 года отменена Высшим судом.

- **Отсутствие — это позиция.** Если считать только присутствовавших, у оппозиции «нет мнения» по одному из самых конфликтных законов созыва. Нужен атрибут `participation_pattern` и правило трактовки бойкота в матче.
- **Судьба после голосования.** Для квиза важно, как голосовали, но атрибут `afterlife` нужен для текста вопроса и объяснения.
- **Шум из оговорок.** Вокруг таких законов идут сотни голосований по оговоркам (הסתייגויות), часть из них тактические. Их нужно помечать и почти всегда исключать.

### 2. Законы против UNRWA (октябрь 2024)

Приняты большим большинством, включая значительную часть оппозиции. Против голосовали в основном арабские партии и часть левого фланга.

- **Не линия коалиции.** Фильтр коалиционной дисциплины такой закон пропустит, и это правильно.
- **Ценность вопроса зависит от контекста.** По общей энтропии вопрос «скучный» (большинство голосует одинаково), но он лучше всех различает партии меньшинства. Это аргумент за адаптивный выбор вопросов.

### 3. Закон о призыве харедим

Многолетний сюжет: законопроекты в нескольких созывах, решения Высшего суда, коалиционные кризисы (в 2025 году из правительства вышли харедимные партии).

- **Один сюжет, много законопроектов.** Нужен атрибут `saga`, чтобы не задавать пять вопросов об одном и том же и связывать голосования через годы.
- **Процедурные голосования.** Например, о «законе о преемственности» (דין רציפות). Партии голосуют по ним тактически.
- **Раскол внутри коалиции.** Здесь `cohesion` блока важнее позиции «коалиции» в целом.

### 4. Законопроект о роспуске Кнессета (июнь 2025, отклонён)

Внесён оппозицией и провален. Часть партий, угрожавших роспуском, голосовала против или не голосовала.

- **Голосование о власти, а не о политике.** Позиция здесь — тактика момента. Такой тип помечается (`kind: procedural_power`) и не используется как вопрос квиза.

## Атрибуты

| Атрибут | Значения | Источник |
| --- | --- | --- |
| `kind` | содержательный / процедурный / тактический (роспуск, вотум недоверия) | вручную + `vote_item_id` |
| `stage` | предварительное, 1-е, 2-е/3-е чтение, оговорка | `vote_item_id` |
| `outcome` | принят / отклонён | `is_accepted` |
| `afterlife` | действует / отменён судом / заменён | вручную |
| `participation_pattern` | обычное / бойкот блока / массовое неучастие | вычисляется из атомов |
| `split_pattern` | линия коалиции / межблочное большинство / раскол внутри блока | вычисляется из атомов + состав коалиции на дату |
| `saga` | идентификатор сюжета (призыв, судебная реформа…) | вручную, связь с KNS_Bill |
| `axes[]` | оси конфликта со знаком | кластеры по поведению партий + ручное название |

Вычисляются автоматически: `stage`, `outcome`, `participation_pattern`, `split_pattern`, кластеры для `axes`.
Требуют человека или внешнего источника: `kind`, `afterlife`, `saga`, названия осей, нейтральный текст вопроса.

## Оси вместо тем

Тематические рубрики («социалка», «экономика») группируют по области политики, а партии делятся по линии конфликта. Пример: зарплаты медикам, оплата первого больничного дня и субсидии ученикам ешив — всё «социалка», но расклады партий по ним, вероятно, разные.

Поэтому оси выводятся из данных: голосования кластеризуются по поведению партий, и только потом кластеры получают человеческие названия. Ручная разметка проверяет и называет кластеры, но не задаёт их заранее.

## Что проверить, чтобы подтвердить или опровергнуть гипотезу

- [ ] Выгрузить голоса депутатов по четырём примерам и проверить, что `participation_pattern` и `split_pattern` корректно вычисляются автоматически
- [ ] Проверить, как в данных выглядит бойкот: отсутствие записи, отдельный код или «присутствовал, не голосовал»
- [ ] Найти, как связать голосования одного сюжета (`saga`) через KNS_Bill
- [ ] Прогнать кластеризацию на 25-м созыве и посмотреть, совпадают ли кластеры с интуитивными осями
- [ ] Оценить, сколько голосований остаётся после фильтров и, соответственно, сколько ручной работы

## Открытые вопросы

- Как трактовать бойкот в матче: как «против» или как отдельное значение?
- Какое правило сопоставления «депутат → партия» использовать по умолчанию: фракция на дату голосования или нынешний список?
- Брать только 25-й созыв или несколько последних?
