# Задание для jef: темы законопроектов

_2026-10-10. Решение Q8 в [SHARED_UNDERSTANDING.md](archive/decision_registry_2026-10-12.md)._

## Что такое jef

jef — это **Jev**, модель компании TypeSafe (`jev-latest`, сейчас `jev-1.13.0`). Работаем через облачный API `POST https://api.typesafe.ai/v1/systemone` с помощью Python SDK `typesafe-sdk`. Документация: [docs.typesafe.ai](https://docs.typesafe.ai/llms.txt).

- **Только классифицирует, текст не пишет.** На вход подаётся `state` (наш законопроект) и вопросы. На выход приходит вероятность для каждого варианта ответа и `confidence`. Сформулировать вопрос квиза или пересказать законопроект модель не может.
- **Типы вопросов:**
  - `choice` — один вариант из списка, до 255 вариантов (у нас это тема);
  - `noul` — вероятность ответа «да» (у нас это `value_laden`);
  - `score` — оценка по шкале.
- **Сравнивает с описаниями вариантов, а не рассуждает.** Точность зависит от того, насколько хорошо написаны описания в [questions.json](../research/questions.json).
- **Цена:** $0,042 за миллион входных токенов, выходные бесплатно. Один запрос (22 описания тем и название) — порядка 1–2 тыс. токенов. Значит, **полный прогон 11 768 законопроектов стоит меньше $1, а пилот — около цента**. Оплаченных $10 хватит на десятки итераций.
- **Лимиты:** 80 запросов в секунду. Скрипт держит 16 параллельных запросов и повторяет их при ошибках 429 и 529.
- **Язык.** По документации английский — основной язык, другие поддерживаются, но хуже. Поэтому название законопроекта передаётся на иврите, а вопросы и описания тем написаны по-английски с ключевыми словами на иврите. Обязательна проверка на эталоне, и на неуверенные ответы нужно смотреть отдельно.
- **Модель не дообучается на наших данных.** Подстраиваем её только формулировками вопросов и описаний.

## Зачем нужна разметка

1. **Сигнал «инициатива» по темам.** Что продвигает каждая партия: по 11 768 законопроектам, а не только по 2 276, по которым голосовали.
2. **Отбор кандидатов в вопросы квиза.** Поможет признак `value_laden`, то есть затрагивает ли законопроект идеологически спорную тему.
3. **Баланс тем в квизе.** Чтобы вопросы не сводились к одной-двум темам.

**Об эталоне.** Его разметил я (Claude) по названиям законопроектов. Это не экспертная разметка. Примерно в 10–15 % случаев тема неоднозначна: например, военные кладбища можно отнести и к «памяти», и к «армии». Если просмотрите 20–30 строк эталона и поправите, оценка станет надёжнее.

## Как запускать

Скрипт [pipeline/jef_run.py](../pipeline/jef_run.py) переводит `questions.json` в вопросы API, отправляет каждый законопроект как `state = {bill_title_hebrew, knesset_term, bill_type}` и пишет в `research/output/results.jsonl` по одной строке на законопроект:

```json
{"bill_id": 2201200, "model": "jev-1.13.0", "questions_version": "topics-v1", "input_tokens": 1450,
 "topic": {"judiciary": 0.91, "governance": 0.05, "...": 0.0}, "topic_confidence": 0.84, "value_laden": 0.88}
```

```bash
python3 pipeline/jef_run.py --dry-run     # показать запрос, без обращения к API
python3 pipeline/jef_run.py --gold        # пилот: 200 законопроектов эталона
python3 research/scripts/jef_eval.py research/output/results.jsonl
python3 pipeline/jef_run.py --all         # полный прогон, продолжает с места обрыва
```

**API-ключ.** Создаётся на [console.typesafe.ai](https://console.typesafe.ai/). Его нужно положить в файл `.env` в корне проекта:

```
TYPESAFE_API_KEY=...
```

Файл `.env` исключён из git. **Ключ не нужно вставлять в чат.**

## Порядок работы

1. **Пилот на 200 законопроектах из эталона.** Прогнать только `bill_id` из `gold.csv`, затем:
   ```bash
   python3 research/scripts/jef_eval.py research/output/results.jsonl
   ```
   Скрипт покажет общую точность, точность при разных порогах уверенности (и какая доля законопроектов при этом принимается автоматически) и темы, которые модель путает.
2. **Решение по итогам пилота:**

   | Мягкая точность | Что делаем |
   | --- | --- |
   | от 85 % | Запускаем на всех 11 768 законопроектах |
   | 70–85 % | Правим описания тем, которые модель путает (это видно в выводе скрипта), и повторяем пилот. Если не помогает, переводим названия на английский перед классификацией |
   | меньше 70 % | jef для этой задачи не подходит. Запасной вариант: размечаю я, LLM-проходом по названиям, это дороже и медленнее |

3. **Полный прогон.** Ответы с уверенностью ниже выбранного порога идут на проверку. Если их до ~1 000, проверяю сам. Если больше, просматриваем по темам.
4. **Загрузка в базу.** Результат кладётся в `manual/bill_topics.csv` (версия вопросов и порог фиксируются в SHARED_UNDERSTANDING.md (обоснования по ID — в архиве реестра)) и подключается в сборку.

А сами расхождения показывают, что **у законопроекта часто две темы**.
- **Путаница идёт между смежными темами:** `haredi_draft` и `service_model`, `police_political_control` и `police_surveillance`. Это вопрос границ в каталоге, а не ошибки модели.

**Вывод: для определения тем по названиям на иврите Jev подходит.** Полный прогон 11 768 законопроектов будет стоить около $3.

**Проверка без ручного эталона: сверка с голосованиями 25-го созыва** (`evidence/jev_direction_vote_check_2026-10-11.txt`). Взяты 265 законопроектов, у которых было спорное голосование и направление выражено явно. Для каждого сравнивается сторона, которую дала модель, с тем, какой блок поддержал законопроект сильнее. Полярность у осей разная: «высокий» полюс по представительству женщин, равенству, ограничению срока премьера, ЛГБТ и госкомиссии — это позиция оппозиции. Поэтому 0 % совпадений означает полную согласованность, только с обратным знаком. Согласованность в обе стороны:

- **90–100 %:** меры против террористов, задержанные по делам безопасности, мигранты, представительство женщин, равенство, судебная система, ограничение срока премьера, UNRWA, деньги ПА, религия и государство, ЛГБТ, борьба с дискриминацией;
- **80–89 %:** СМИ, лояльность, госкомиссия, полномочия полиции, внешняя политика, призыв;
- **около 67 %:** суверенитет и свобода слова.

**Расхождение не всегда ошибка модели.** Ястребиные законопроекты вносит и правая оппозиция, например «Исраэль Бейтейну» («объявить Катар враждебным государством»), а коалиция их блокирует. Модель тут права, расходится сама проверка. Поэтому сверка с блоками — это проверка на здравый смысл, а не эталон.

## Тексты законопроектов: когда они помогают (2026-10-11)

`pipeline/bill_texts.py` скачивает текст законопроекта из `KNS_DocumentBill` (DOCX: иврит извлекается чисто, PDF ломает порядок символов справа налево) и вырезает раздел «דברי הסבר». В Jev идут первые 3 000 знаков этого раздела, поле `explanatory_notes_hebrew`.

**Эталон исправлен по текстам.** Три законопроекта про еду в больницах на Песах на самом деле религиозные: они разрешают больницам запрещать хамец. Я по названию отнёс их к либеральным. «Закон о браке и разводе» — компромисс, а не гражданский брак. По одному названию ошибся и человек.

| Вариант (61 законопроект эталона) | Призыв | Суверенитет | Религия | Судебная система | Всего |
| --- | ---: | ---: | ---: | ---: | ---: |
| Только название | 20/20 | 10/10 | 8/10 | 17/21 | 55 |
| Название и записка всегда | 20/20 | 10/10 | 10/10 | 10/21 | 51 |
| **Записка только при уверенности по названию ниже 0,7, кроме судебной темы** | 20/20 | 10/10 | 10/10 | 17/21 | **57** |

- **Записки — это агитация в пользу законопроекта.** Где тема спорна по существу, модель принимает аргументацию автора. Законопроекты о разделении должности юрсоветника правительства и о генеральном прокуроре обоснованы как защита верховенства права. С запиской модель ставит их на сторону «независимости», с уверенностью около 0.
- Формулировка «оценивай механизм, а не обоснование» не помогла: 15 из 21 по названию, 11 из 21 с текстом.
- **Вывод:** по судебной теме направление определяется по названию, а для законопроектов с голосованием — по тому, какой блок их поддержал.
- **Нестабильность:** повторный прогон тех же запросов меняет сторону у 1–2 пограничных законопроектов (балл около 2,5). Значения, где расстояние от середины шкалы меньше 0,5, нужно считать «нейтрально или неясно».
- Прогон с текстом стоит $0,005 на 61 законопроект: записки примерно в 4 раза длиннее запроса по названию.

## Переписанные шкалы направления (2026-10-11)

У семи шкал была высокая доля ответов «нейтрально» (50–81 %). Выборка законопроектов показала, что шкала спрашивала про другой спор, чем тот, о котором законопроекты. Прежние версии сохранены в `axes.json` → `_revisions`.

| Шкала | Что изменено | «Нейтрально», было → стало |
| --- | --- | --- |
| Полиция | Не только «контроль министра», а «надзор и ограничения ↔ полномочия и политическое руководство» | 81 % → 23 % |
| Иммунитет | Привилегии и подотчётность депутатов, а не только иммунитет | 76 % → 14 % |
| Святые места | Развилка: вопрос «да/нет» «про Храмовую гору?» и две шкалы в одном запросе (статус-кво Храмовой горы; плюрализм ↔ ортодоксальный контроль у Стены Плача) | 75 % → 59 % |
| Религия и государство | Добавлена власть раввината, раввинских судов и кашрута | 52 % → 46 % |
| Харедимное образование | «Условия финансирования ↔ финансирование с автономией», явно названы государственный харедимный поток и «признанные неофициальные» школы | 50 % → 21 % |
| Застройка в арабском секторе | Явно названы закон Каминица, сносы и штрафы | 43 % → 22 % |
| Назначения в госслужбе | Механизм: кто назначает, министр или фильтры (Комиссия по гражданской службе, юрсоветник) | 53 % → 60 % |

Выборочная проверка уверенных ответов по новым шкалам сходится с ожиданием. Например: отмена подчинения полиции министру → «надзор»; национальная гвардия → «полномочия»; тайное голосование по иммунитету → «привилегии»; консультации раввината на святых местах → «ортодоксальный контроль».

**Известная слабость в понимании иврита.** «להגבלת הריסה וענישה» («ограничение сносов и наказаний») модель стабильно читает как ужесточение, с уверенностью около 0. Такие законопроекты по правилу Q15 получают текст записки.

Эталон по религии с новой шкалой: по названию 5 из 10 (все промахи — «нейтрально» при низкой уверенности), с запиской 10 из 10, по гибридному правилу 9 из 10. Повторные прогоны дают разброс в 1–2 законопроекта.

## Название или записка: где теряется направление (2026-10-11)

Гибридное правило применено ко всем законопроектам: 1 666 законопроектов с уверенностью по названию ниже 0,7 (кроме судебной темы) пересчитаны с запиской, **$0,14**. Результат: `research/output/direction_text.jsonl`. В итоговом ответе запись с текстом заменяет запись по названию. В сверке с голосованиями 25-го созыва теперь 309 законопроектов (было 265), согласованность по осям прежняя: по религии 17 из 17.

**Сравнение двух ответов по 1 666 неуверенным законопроектам:**

| Что произошло | Доля |
| --- | ---: |
| Записка подтвердила сторону, которую дало название | 62 % |

| **Название и записка указывают в противоположные стороны** | **4 % (70)** |

**Кто прав, когда они расходятся.** Вручную разобран 21 случай: в 19 права записка. Название вводит в заблуждение по трём причинам:

- **Эвфемизм в названии.** «Закон о возвращении (поправка — права членов семьи)» на деле отменяет пункт о внуках, то есть сужает право на возвращение. «Разрешение на возбуждение дела против полицейских, участвовавших в националистическом инциденте» на деле защищает полицейских.
- **Модель плохо читает иврит.** «Ограничение сносов и наказаний» она читает как ужесточение.
- **Нейтрально звучащее название.** «Отмена Гражданской администрации» звучит как административная мера, а на деле означает передачу Иудеи и Самарии под гражданское управление Израиля, то есть шаг к аннексии.

**Где расхождений больше всего:** кто является евреем (48 % неуверенных законопроектов этой темы), полиция (17 %), застройка в арабском секторе (14 %), свобода слова (14 %), призыв (12 %), иммунитет (12 %), воссоединение семей (11 %).
**Где название чаще всего «молчит»:** задержанные по делам безопасности (43 %: «продление чрезвычайных положений»), религия (35 %), полномочия полиции (35 %), права подозреваемых (33 %), воссоединение семей (33 %), назначения в госслужбе (32 %).

**Вывод.** Спекулятивные названия-эвфемизмы есть, но они сосредоточены в темах гражданства, идентичности, полиции и свободы слова. В остальных темах названия скорее формальные, чем манипулятивные: направление просто не видно без текста. Обратная картина (агитирует записка, а не название) подтверждена только в судебной теме, поэтому она исключена из правила Q15.

**Направление** (60 законопроектов со шкалой):

- **Сторона.** Шкала подошла по мнению разметчика, и Jev вынес решение: 45 законопроектов, совпадение **42 из 45 (93 %)**. При высокой надёжности Jev 32 из 35, при средней 10 из 10. Два из трёх расхождений — ошибка разметчика: «отмена статьи об оскорблении госслужащего» он поставил на полюс «ограничивает свободу слова», хотя законопроект её защищает. - **Главная находка: шкала не подходит в 22 % случаев.** По мнению разметчика, у 13 из 60 законопроектов спор не тот, о котором спрашивает шкала. При этом **11 из них Jev «решил»**, то есть дал направление по неподходящей шкале. Примеры: равенство ролей для женщин в армии попало в «модель службы»; урегулирование поселений — в «застройку в арабском секторе»; запись разговоров в яслях родителями — в «полномочия полиции». Ещё несколько — правительственные поправки без записки, где связь со шкалой не видна. Причина в устройстве вопроса: шкала задаётся с допущением «законопроект касается X», и модель обязана ответить, даже если не касается. Ошибка в теме и широкая тема дают ложный сигнал направления.

**Вывод:** если шкала подходит, сторона определяется надёжно (93 % без поправок). Главный источник ошибок — сигнал направления там, где шкала неприменима: около 20 % решённых законопроектов. Нужна общая для всех шкал проверка применимости.
