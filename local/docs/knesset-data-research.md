# Ресерч: публичные данные Кнессета для квиза

_Актуально на 2026-10-10_

## Задача

Нужно выяснить, позволяют ли официальные открытые данные Кнессета собрать набор голосований, по которому квиз сопоставит ответы пользователя с позициями партий. И если позволяют, то как именно их выгрузить.

Ресерч готов, когда подтверждено, что можно получить:

- финальные голосования по законам выбранных созывов с поимёнными результатами;
- фракцию каждого депутата на дату голосования;
- признак, по которому можно отсеять голосования с коалиционной дисциплиной;
- направление голоса относительно законопроекта («за закон» / «против»).

Источники только официальные: OData-сервисы Кнессета, сайт main.knesset.gov.il и «Решумот». Сторонние агрегаторы (knessetvotes.org.il, Open Knesset) используются только для сверки. Данные готовятся заранее и кладутся в статику: сервис недоступен из-за пределов Израиля.

**Открытый вопрос:** берём только 25-й созыв или несколько последних? От этого зависит объём работы с фракциями.

## Легенда

**Критичность**

- **Критично**: без этого квиз выдаст неверный результат.
- **Важно**: заметно влияет на качество или на трудоёмкость.
- **Желательно**: улучшение, первая версия обойдётся без него.

**Статус**

- **Проверено**: подтверждено реальным запросом к сервису.
- **Частично**: подтверждено на части данных (например, только на 16-м созыве).
- **Не проверено**: известно по памяти или это предположение, нужен запрос.

Поиск в интернете в этом ресерче ничего по теме не подтвердил: ни про knessetvotes.org.il, ни про схему OData. Всё со статусом «Проверено» опирается на ответы сервиса, полученные из Израиля.

## Рабочие запросы к Votes.svc

JSON сервис отдаёт только в verbose-режиме и только запросам из Израиля. Этот запрос проверен:

```bash
curl -s -H "Accept: application/json;odata=verbose" \
  "https://knesset.gov.il/Odata/Votes.svc/View_vote_rslts_hdr_Approved?\$top=2" | jq
```

А этот, с фильтром, ещё нет (задача 4). Флаг `-v` покажет, какой URL ушёл на сервер:

```bash
curl -sG -v "https://knesset.gov.il/Odata/Votes.svc/View_vote_rslts_hdr_Approved" \
  -H "Accept: application/json;odata=verbose" \
  --data-urlencode '$filter=knesset_num eq 25 and vote_item_id eq 102M' \
  --data-urlencode '$top=5' 2>&1 | grep '^> GET'
```

Что учитывать при разборе ответа:

- данные лежат либо в `d`, либо в `d.results` (когда есть пагинация), поэтому в jq берём `.d.results // .d`;
- `vote_date` приходит как `/Date(1066608000000)/`, это миллисекунды Unix;
- `vote_item_id`, `session_id` и `sess_item_id` приходят строками;
- `modifier`, `vote_type`, `vote_stat` и `reason` на выборке несут служебные значения, для квиза не нужны.

## Ближайшие проверки

Эти четыре запроса закрывают большую часть критичных непроверенных задач (4, 5, 6, 7, 9):

- [ ] Запустить запрос с фильтром и `-v` и проверить, что `$filter` доходит до сервера и применяется
- [ ] Открыть `Votes.svc/$metadata` и сверить точные имена таблиц с поимёнными голосами и кодами результата
- [ ] Посчитать распределение `vote_item_id` в 25-м созыве
- [ ] Открыть `ParliamentInfo.svc` и найти таблицы с историей фракций депутатов
